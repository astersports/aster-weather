# @aster/weather v0.9.0 — production-ready release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `v0.9.0`, a release with no known open defects: alert lists say when they were fetched and whether they are stale (B-018), a clock that steps back never makes a cached reading fresh (B-017), and the nine open Dependabot alerts are closed.

**Architecture:** B-018 is additive. A new `getAlertsReading` returns `{ alerts, fetchedAt, stale }` from the existing cache meta. `getAlerts` keeps its shape and is built on it, and `WeatherReport` gains `alertsReading`. B-017 mirrors B-016's guard (`elapsed >= 0 && elapsed < limit`) in `WeatherCache`. Development dependencies are bumped and `dist/` is rebuilt and committed.

**Tech Stack:** TypeScript 6, vitest 5, pnpm 10.4.1, zero runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-11-27-one-weather-engine-design.md`. Owner rulings of 2026-11-27 in this session:
- "Library, production-ready".
- "v0.9.0 now, renumber the rest": icons → `v0.10.0`, page parts → `v0.11.0`, UV/outlooks → `v0.12.0`.
- The owner approves the `v0.9.0` tag when the PR is green, and is asked first.

## Global Constraints
- Zero runtime dependencies. `dist/` committed. `react` stays an optional peer.
- The engine never throws; `onError` fires once per ultimately-failed fetch (CLAUDE.md §3).
- SemVer here: minor = additive. This release is additive, so it is `0.9.0`.
- Never add `[release-approved]` without Frank's explicit yes.
- Tests run on recorded fixtures with no live network. `pnpm run test`, never a bare `vitest run`.
- Done = `pnpm run check && pnpm run test && pnpm run build`, and `git status` shows no uncommitted `dist/`.

## Review Focus
1. A refresh that fails within `ALERT_MAX_STALE_MS` serves the last list with `stale: true` and the *original* `fetchedAt`, never `now()`. Test it in Task 1.
2. A clock that steps back by an hour after a fetch: the entry is not fresh, so the loader runs. If the loader fails, the entry is served with `stale: true`. Test it in Task 2.
3. `getAlerts` output is byte-identical to v0.8.0 for the same fixtures (no shape change). Test it in Task 1.
4. A `null` alert answer (outside coverage, or no list young enough) stays `null` in `getAlertsReading` and in `WeatherReport.alertsReading`. Test it in Task 1.
5. After the happy-dom 20 → 21 major, the icon tests still render (happy-dom is their DOM). The full suite must pass in Task 3.

### Task 2: A clock that steps back never makes a cached reading fresh (B-017)

**Files:**
- Modify: `src/cache.ts`:
  - `get` :99. It also gains an injectable `now: () => number = Date.now` as its 5th parameter, for testability.
  - `getWithMeta` :166.
  - `peek` :220-222.
- Test: `src/__tests__/resilience.test.ts`, a new describe "B-017: a clock that stepped back".

**Interfaces:** No public change. Internal: a reading is fresh only when `age >= 0 && age < freshMs`.

- [ ] **Step 1: Write the failing tests.** Use `new WeatherCache<number>(TTL)` and an injected clock.
  - Cache at T. Then:
    - With the clock at T−1 h, `getWithMeta` calls the loader again (count the calls).
    - If that loader fails, the result is the cached value with `stale: true` and `fetchedAt: T`.
    - `peek` at T−1 h returns `stale: true`.
    - `get`, with the injected clock, at T−1 h calls the loader.
  - Control: at T + TTL/2 the entry is fresh with no load.
- [ ] **Step 2: Run them; they fail.** The entry is served fresh with no loader call.
- [ ] **Step 3: Implement.**
  - Name the guard `const isFresh = (age: number, limit: number) => age >= 0 && age < limit` in cache.ts, with the B-016 comment style.
  - Use it at the three sites.
  - The stale fallback at :185 keeps `age <= maxStaleMs`, so a reading of negative age can still be served, but only as `stale: true`.
- [ ] **Step 4: Run `pnpm run test`; it passes.** Mutation-check: drop `age >= 0`, confirm red, restore.
- [ ] **Step 5: Commit** `fix: a clock that steps back never keeps a cached reading fresh (B-017)`.
